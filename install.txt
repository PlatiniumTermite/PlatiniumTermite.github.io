FLOW — PLAIN INSTALL GUIDE
==========================
What Flow is: a continuity app. Devices on the same Wi-Fi find each other
when the network allows discovery, pair with approval, and share files, folders, text, clipboard,
screens, and keyboard/mouse. Works between Windows, Mac and Android.
iPhone/iPad join through Safari — no install needed.

INSTALL — WINDOWS
-----------------
1. Download and open the Setup.exe.
2. Review any OS warning and verify the download against the release checksums.
3. Install finishes → Flow runs from the system tray (bottom-right clock area).

INSTALL — MAC
-------------
1. Download and open the DMG (arm64 for Apple silicon, x64 for Intel).
2. Drag Flow onto Applications. Eject the image.
3. Open Flow from Applications once. It lives in the menu bar (top-right).
4. When macOS asks: allow Local Network (needed to find devices),
   Screen Recording (only for screen sharing), Accessibility (only for
   keyboard/mouse linking).

INSTALL — ANDROID (needs Android 7+)
------------------------------------
1. Download the APK on the phone and open it.
2. Android asks once to allow installs from your browser — allow it.
3. Tap Install, then Open.
4. Keep the phone on the same Wi-Fi as the computers.

INSTALL — IPHONE / IPAD (no app needed)
---------------------------------------
1. On a computer, open Flow → Connect a device → show the "Web browser" QR.
2. Scan with the iPhone camera → Flow opens in Safari, already paired.
   iOS limits apply: no auto-discovery, transfers need Safari open.

OS WARNINGS AND PERMISSIONS
--------------------------
These are engineering alpha builds. Windows publisher signing and Mac
Developer ID notarization are not configured. Warnings can recur on updates;
managed work/school computers may block installation. Verify checksums against
the official GitHub release before deciding whether to install. A warning is
not proof of corruption, and lack of a warning is not proof of safety.

Flow's Device setup opens after launch. Use the permission buttons for the
features you want: Local Network for discovery, Accessibility and Input
Monitoring for Mac input linking, and Screen Recording for Mac display sharing.
Return to Flow to refresh the status. Windows Firewall may request access for
Flow; allow it on the network you use. Do not disable the firewall.

HOW TO USE (after install on both devices)
------------------------------------------
1. Put both devices on the same Wi-Fi.
2. Complete Device setup. On networks that allow discovery, they appear automatically — on computers, in the menu-bar/tray menu
   under "Nearby devices"; on Android, under Nearby.
3. Click a device to pair → the other side approves → connected.
   You never need to open the main window.
4. Then: send files/folders/text from the tray "Send to" menu,
   Windows right-click "Send to → Flow", Finder "Open With → Flow",
   or Android's share sheet. Clipboard syncs by default.
5. Incoming files notify — click the notification to accept.

WHEN NEARBY DEVICES DO NOT APPEAR
--------------------------------
Keep Flow open and discovery enabled on both computers. Check Local Network
permission on Mac and firewall access on Windows. College/guest Wi-Fi and some
hotspots block device-to-device traffic even when both devices have Internet.

On the computer hosting your space, choose Connect a device → Internet
invitation and share that complete link with the other computer. Keep the host
running. This uses a bundled public HTTPS tunnel when the service is reachable.
Data can fall back to signaling; screen video still needs a WebRTC media route.

UPDATES
-------
Windows updates itself in the background (tray → "Check for updates…").
Mac shows a notification linking to the download — install manually.
Keep both devices on the same version.

CURRENT LIMITS
--------------
Flow is an engineering alpha, not a guaranteed equivalent of Apple Continuity.
- Network isolation can block discovery and direct connections.
- Windows signing and Mac notarization are not configured for these builds;
  OS warnings or blocks can recur.
- Physical Mac-to-Windows input on every network has not been verified.
- Internet services can be unavailable. The signaling fallback authenticates
  messages and uses TLS with HTTPS, but its payloads are visible to the host.
- Windows extended display needs an existing independent monitor or a
  separately installed virtual-display driver.
- iPhone/iPad currently join through Safari; background behavior is limited.
